## Context

参见 `proposal.md` 的动机和 `specs/reading-time-estimation/spec.md` 的行为合同。当前 `ReadingTimeEstimator` 对单位前进耗时先裁剪到旧估计的 `0.25～4` 倍，再以固定 `α=0.2` 更新；因此一个 4 倍慢样本会把速度估计直接放大为原来的 1.6 倍，而且阅读一小时后单页仍保持相同杠杆。当前阅读位置使用页面末端进度，翻到下一页时还可能把上一页停留时间与下一页内容量配对。

现有实现已经具备适合低功耗演进的边界：估算核心位于纯 Kotlin 类中，速度状态嵌入 `Book.ReadConfig`，章节索引使用可重建 sidecar；索引线程为最低优先级，按最多 64 章或约 8 ms 分片并让出约 50 ms，速度状态约 120 秒批量保存，索引连续变化最多约 30 秒写盘一次。新设计必须复用这些边界，不修改 Room、书源规则、正文格式、导入接口或最低 API 21，也不能引入第三方统计依赖。

## Goals / Non-Goals

**Goals:**

- 让每个样本的内容量与其真实可见停留区间严格对应，消除错页配对。
- 使孤立异常的影响随累计证据自然减小，同时在用户真实持续变快或变慢时对称跟随。
- 统一使用可见文本单位训练速度和估算剩余量，并以低成本代理覆盖未加载章节。
- 把速度和剩余量不确定性显式纳入“学习中/可显示”判断。
- 保持翻页新增工作有界、仅访问内存、事件驱动，并以低端真机延迟、稳态分配和热路径审计作为本次发布门禁。
- 让算法、索引校准、迁移和确定性轨迹可以在 JVM 单元测试中验证。

**Non-Goals:**

- 不声称复刻 Kindle、静读天下或其他闭源产品的内部算法。
- 不为 ETA 主动下载、解压、解析、净化或分页整本正文，也不增加充电或息屏补索引任务。
- 不覆盖漫画、音频书、朗读速度或图片观看时间建模。
- 不增加全局读者画像、跨书速度先验、用户可调算法参数、置信区间 UI 或 Room 数据表。
- 不以 ETA 显示限幅、固定一小时锁定或低电量双算法切换满足验收。

## Decisions

### 1. 以“先显示、后结算”的稳定锚点修正样本配对

阅读层在页面真正可见且排版稳定时创建 `ReadingSpanAnchor`。锚点保存当前可见文本区间、章节身份、起始单调时钟、是否重读和文本可靠性，而不是只保存页面末端的抽象进度。发生正常向前事件时，先用旧锚点所代表的已显示内容和从旧锚点开始累计的有效停留时间提交样本，再为新页面建立锚点。这样用户阅读第 N 页的时间不会再与第 N+1 页的内容量配对。

同一稳定区间内的微小滚动或分页事件累积停留时间和内容量，直至形成下一个稳定锚点；不设置“少于 5 秒就丢弃”的硬门槛。回退、目录跳转、进度条跳转、排版重建、Activity 遮挡、朗读和初始化会使旧锚点失效并重新布点，不提交跨越这些事件的样本。跨章节正常前进仍可提交旧页样本，因为内容量在旧锚点建立时已经确定。

为区分重读，状态保留本书曾经到达的最高语义坐标。完全位于已读范围的正常样本可以完整进入近期模型，但通过连续的新颖度权重显著降低其长期证据；位置跳转本身仍不训练。

替代方案是继续用相邻页面末端坐标相减，但它无法解决当前的错页配对，且排版变化会改变进度比例，因此不采用。

### 2. 在现有正文处理与排版遍历中累计可见 Unicode 单位

内容单位定义为最终可见文本中的 Unicode 码点数：忽略结构性空白，保留文字、数字和标点。标题如果实际显示则计入；图片和结构占位不换算成固定字数。计数逻辑使用平台字符 API，兼容 API 21，不增加 Unicode 库。

同步排版和异步 `TextChapterLayout` 都已经逐段处理净化、替换后的文本。实现应在这些既有循环中同步累计页面和章节可见单位，并把页面单位、章节内可见前缀和图文可靠性保存到排版实体；不得在翻页时重新扫描 `TextPage.text`。章节已经自然排版完成时，阅读层向索引管理器提交“章节身份、原始代理长度、可见单位数”，这是机会式观察，不触发额外正文读取。

图文可靠性根据既有文本行、图片列或排版占用信息计算连续权重。纯图片页趋近零文本训练权重；混合页面平滑降权。实现不读取图片像素、不运行图像分析，也不把图片观看时间加入文本速度。

替代方案是启动时扫描全书得到精确字符数，精度更高但违反功耗和内容访问边界；始终使用原始字节则无法解决编码、替换和章节结构差异，因此采用机会式精确计数与代理校准。

### 3. 在对数耗时域建立近期鲁棒模型

每个样本记录：

```text
x = ln(实际有效停留秒数 / 实际可见文本单位)
```

对数域让相同百分比的变快和变慢近似对称。近期证据保存在固定容量的原始类型环形缓冲中，至少包含 `x`、有效证据时长、有效阅读年龄、重读权重和图文可靠性。缓冲和排序草稿数组在估算器创建时一次分配；每次有效样本提交时才重算，普通查询、页面重绘和静止停留不运行统计计算。

近期样本权重由三部分相乘：

1. 按累计有效阅读时长而非自然时间计算的指数衰减；
2. 重读、图文占比和事件语义产生的上下文可靠性；
3. 根据稳健残差得到的 Student-t 或 Cauchy 连续异常权重。

先用上下文权重和时间衰减求加权中位数，再用加权 MAD 求离散度；之后根据标准化残差计算 Student-t/Cauchy 权重并得到近期中心。MAD 使用与单位无关的数值下限避免稳定轨迹出现除零，但不对 ETA 或样本耗时做上下限裁剪。

异常长停留仍以实际耗时形成 `x`，但它推进“有效阅读年龄”的时长使用相对当前稳定速度的连续饱和函数，而不是原始墙钟时长。这样长时间忘记翻页会得到接近零的稳健影响，也不会一次把全部近期证据老化掉。模型尚未成熟时使用同样连续的软饱和初值，不恢复 5～120 秒硬丢弃区间。

算法思想参考 AndroidX Media3 `SlidingPercentile` 的加权滑动分位数，但不复制其代码：本设计还需要对数域 MAD、上下文权重和按有效阅读时间衰减。固定最近 50 页中位数虽然类似 Readest 且足够简单，但会在第 51 页产生边界效应，无法同时表达长期证据，因此不采用。

### 4. 用证据量融合近期中心与本书长期中心

长期模型保存对数速度中心、离散度和有效证据量。只有新的有效阅读证据到来时，旧长期证据才按较慢时间尺度指数衰减；应用闲置、退出或数日未打开不会按自然时间使本书模型失效。长期更新接收已经经过上下文和异常可靠性处理的近期证据，不直接接收原始极端样本。

近期中心与长期中心在对数域按各自有效证据量和离散度连续融合。融合权重由证据产生，而不是每页固定 `α`：成熟长期模型对单页具有很小杠杆，持续的新速度会逐渐积累近期证据并同时推动长期中心。参数通过规范中的确定性轨迹联合调优，具体半衰期、自由度和缓冲容量不是外部合同。

缓冲达到容量时，淘汰前先把旧证据的剩余有效质量折入长期摘要；淘汰可以部分折算，不做“突然删除一个完整页面”的离散切换。实现参数必须同时满足折叠前后速度变化不超过约 0.5% 和功耗门禁。

这一双时间尺度思想与 hls.js 的快慢估计器相近，但本设计不使用双 EWMA 直接处理原始样本；长期稳定性来自证据量、稳健中心和离散度，近期响应来自按有效阅读时长衰减的鲁棒分布。Liseur 的时间域与证据融合提供了架构参考，但不作为依赖或逐行实现来源。

### 5. 用双置信度决定展示，不修改内部 ETA

速度置信度是有效证据量的单调增函数、离散度的单调减函数；剩余量置信度综合精确可见单位覆盖率、代理校准离散度、未知章节比例和当前章节映射可靠性。两者都达到展示阈值时才返回 `Ready`，否则返回 `Learning`。阈值只是离散 UI 状态的必要决定边界，不参与速度或 ETA 数值计算。

内部 ETA 始终为融合后的单位耗时乘以剩余可见单位期望。系统只向用户显示单一值，不输出尚无产品设计支撑的区间；但测试和诊断可以读取两类置信度及其原因。目录追加或已知章节长度变化直接改变剩余单位，不经过速度平滑；后台只替换内存快照，页面文字仍在下一次既有刷新时更新。

旧的“5 个样本且 60 秒”门槛无法表达证据离散度和剩余量不确定性，因此移除。成熟摘要恢复且剩余量可靠时可以立即显示，新书或长期高离散书籍则保持“学习中”。

### 6. 将章节索引扩展为原始代理、可见单位和不确定性快照

sidecar 升级为新版本，每章保存原始代理长度和已观察可见单位；内存快照另外构建可见单位期望、方差或等价离散度、前缀和、已知覆盖率和目录身份。翻页查询只做数组定址和前缀差。

对同时拥有原始长度和可见单位的已观察章节，在对数比例域计算本书稳健校准中心与 MAD。未观察但原始代理已知的章节使用该比例换算；没有原始代理的章节使用本书已观察章节可见长度的稳健分布。校准样本不足或离散度过高时，估计逐步向章节级退化结果收缩，并降低剩余量置信度，不使用跨书固定比例。

现有最低优先级索引任务继续只检查目录元数据和 `File.length()`，保留最多 64 章、约 8 ms 工作片和约 50 ms 让出策略。它不得读取正文。可见单位只由正常正文处理回调增量写入；连续变化继续使用现有约 500 ms 快照防抖和约 30 秒 sidecar 写入防抖。

旧 sidecar 版本中的原始长度仍有价值。新解码器读取旧数组后把可见单位标为未知，并在下次正常写入时升级格式；损坏、身份不符或无法兼容的 sidecar 仍按现有规则重建。目录末尾纯追加保留校准和速度摘要，换源或非末尾目录变化继续失败关闭并重置。

### 7. 仅持久化紧凑鲁棒摘要，不保存原始近期缓冲

`ReadingTimeState` 升级版本，保存近期中心、近期离散度、近期有效证据量、长期中心、长期离散度、长期有效证据量、最高语义坐标和既有身份字段。环形缓冲属于会话内状态，不进入 `Book.ReadConfig`、Parcelable 备份或 sidecar。

恢复时把兼容近期摘要作为有离散度和证据量的伪证据，与新会话缓冲连续融合；随着新样本到来，它自然衰减并被替代。这样成熟书籍无需重新预热，也不会为每本书保存数百个翻页事件。

旧版本 EWMA 的中心、裁剪语义和证据权重无法无损映射，因此 `ReadingTimeState` 旧版本直接失效，不尝试猜测转换。累计阅读记录、Book 进度、正文缓存和兼容的章节原始长度索引不受影响。状态仍通过现有约 120 秒节流保存，在暂停、换书、重置和生命周期收尾时强制刷新；进程强杀可以损失最近约 120 秒证据。

不修改 Room schema、`app/schemas`、备份入口或规则格式。旧应用回退时会忽略新的 JSON 字段；若无法识别新 sidecar，则只会丢弃可重建索引，不损坏正文。

### 8. 把功耗约束实现为架构不变量和分层证据

翻页热路径只允许读取当前锚点、页面预计算单位、固定缓冲、紧凑摘要和不可变索引快照。不得执行文件、数据库、网络、JSON、章节遍历或 per-page sidecar/Book 写入。统计仅在有效样本提交时运行，静止页面没有定时计算；不新增 `AlarmManager`、WorkManager、前台服务、唤醒锁或充电广播任务。

实现优先使用 `DoubleArray`、`LongArray`、`IntArray` 和复用草稿缓冲，避免 boxed 集合和每样本临时对象。若固定数组排序无法在低端设备满足 P95 0.5 ms，先优化选择算法或减少等价工作；不得通过放宽稳定性合同、改成后台持续计算或低电量回退旧模型解决。

验证分三层：

- 纯 Kotlin 确定性重放验证稳定性、污染、速度阶跃、对称性、证据折叠和迁移；同时记录每次样本更新耗时与分配。
- 在低端真机上测量有效样本提交和缓冲折叠的 P50/P95 与线程分配，并静态审计翻页调用链；P95 不高于 0.5 ms、稳态零堆分配以及没有新增定时器、唤醒锁、后台服务、网络、正文读取和逐页写盘是本次发布门禁。
- 一小时旧版/新版交叉 A/B 仅在设备能够提供可隔离、可重复的 CPU、I/O 与功耗计量时执行。当前目标设备由外部供电、缺少 `powerstats`，电池计数器又拒绝 shell 访问，无法支持 3% 差异结论；产品所有者明确选择单用户灰度并在日常阅读中观察耗电、发热、卡顿和写盘异常。该观察不能追认“能耗差异不超过 3%”，出现明显回归时必须停止继续推广或回退。

对照基线保留当前固定 EWMA 的测试实现或离线重放结果，不在正式运行时保留双算法。KOReader 的累计秒/页、Calibre 的均值与标准差拒绝、Readest 的近期中位数可作为离线比较基线；它们不同时满足本变更的异常稳健性、持续跟随和内容归一化要求。

### 9. 保持参数可调，但把行为轨迹作为不可回避的合同

近期衰减尺度、长期衰减尺度、Student-t/Cauchy 形状参数、MAD 数值下限、展示置信阈值和缓冲容量都集中定义并由确定性测试调优。规范只固定用户可观察的收敛、抗污染、跟随、折叠和功耗结果，因此未来可以替换加权选择算法而不改变产品行为。

调参过程必须同时重放稳定速度、单异常、10% 污染、正负 25% 阶跃、短章、长章、重读、图文混合和目录追加轨迹。任何只在最终 ETA 上限幅、针对单条验收轨迹写特例或牺牲反向速度变化的参数都不合格。

## Risks / Trade-offs

- **[机会式可见单位覆盖增长较慢]** → 未加载章节使用本书代理校准并把离散度纳入剩余量置信度；证据不足时保持“学习中”，不扫描全文换取表面精度。
- **[对数域稳健模型可能响应过慢]** → 用近期与长期证据连续融合，并以正负 25% 阶跃的 15/35 分钟轨迹联合调参，禁止只优化稳定场景。
- **[异常长停留在冷启动期缺少可靠中心]** → 使用连续软饱和的有效时长初值和加权中位数，不恢复固定最大秒数；冷启动期间置信不足则不展示。
- **[Unicode 计数增加正文处理 CPU]** → 在既有净化/排版遍历中融合计数，不二次扫描，不在翻页时计数；以低端真机微基准和发布后单用户观察发现明显回归。
- **[图片、复杂替换或书源正文使代理比例离散]** → 连续降低校准和页面证据权重；剩余量置信不足时退化或保持“学习中”。
- **[固定容量仍可能形成资源边界]** → 淘汰前折入长期摘要，并以折叠造成的速度变化不超过约 0.5% 作为容量选择条件。
- **[紧凑摘要不能重建全部历史分布]** → 保存中心、离散度和有效证据量作为伪证据；接受强杀时丢失最多约 120 秒近期细节，避免逐页写盘和备份膨胀。
- **[真机能耗测量噪声掩盖小差异]** → 明确记录“无法证明 3% 差异”并由产品所有者接受单用户灰度风险；不得把缺少证据写成功耗通过，具备可靠计量条件后再补交叉 A/B。
- **[sidecar 升级与回退版本不互认]** → 新版本兼容读取旧原始长度；旧版本遇到新 sidecar 时仅重建可恢复索引，不影响正文、进度或累计记录。

## Migration Plan

1. 将 `ReadingTimeState` 版本升级并实现兼容读取：新版本摘要正常恢复，旧 EWMA 状态只清除速度字段，保留书籍其他配置与累计记录。
2. 升级 sidecar 编解码；读取旧版本时保留原始长度、把可见单位标记为未知，并在正常增量写入时原子升级。
3. 接入页面可见单位与稳定锚点后，先通过纯 Kotlin RED 测试证明旧 EWMA 在目标轨迹失败，再实现鲁棒模型并使轨迹转绿。
