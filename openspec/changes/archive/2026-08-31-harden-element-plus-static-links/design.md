## Context

参见 `proposal.md` 的动机。本变更开始时，Element Plus `el-link` 会把 `href` 直接交给原生
锚点，上游 `2.11.0` 只增加安全文档；GitHub 对同一漏洞在 `modules/web/package.json` 与
`modules/web/pnpm-lock.yaml` 分别保留一条中危告警，且没有组件级修补版本。仓库内只有
`SourceHelp.vue` 使用 `el-link`，共 11 个源码固定目标，没有 `:href` 或其他运行时数据流。

网页端已有固定 pnpm、冻结安装、类型检查、只读 ESLint、构建和章节 HTML 安全测试，Web
质量任务由 `.github/workflows/test.yml` 运行，`.github/scripts/test_maintenance_workflow.py`
负责保证关键命令不会从持续门禁中静默消失。网页端构建会同步产物到
`app/src/main/assets/web/vue/`，因此源文件变化必须与生成产物精确对账。

## Goals / Non-Goals

**Goals:**

- 把当前 11 个固定链接及其文字、目标、新窗口和来源隔离要求固化为可执行合同。
- 在不依赖网络、浏览器登录态或新增依赖的前提下阻止未知固定目标和动态 URL 绑定。
- 让安全合同成为现有稳定聚合门禁的一部分，并以真实 RED/GREEN 证明其有效。
- 保留两条告警作为上游监测信号，不夸大调用侧缓解的作用。

**Non-Goals:**

- 不升级、替换、补丁化或移除 Element Plus，也不修改 Vue、pnpm lockfile 或其他依赖。
- 不实现通用 URL sanitizer 或 `SafeLink` 组件；当前不存在获准的动态 URL 需求。
- 不改变链接文字、目标、图标、布局和新窗口打开方式。
- 不修改 Android 最低 SDK、Room、规则格式、导入接口、备份、持久化数据、包名、签名或
  Release 流程。
- 不关闭、dismiss 或重新分类现有 Dependabot 告警。

## Decisions

### 1. 使用全源码精确清单，而不是只检查单个组件中的危险字符串

新增一个仅使用 Node.js 内置模块的确定性脚本，递归扫描 `modules/web/src/` 中所有 Vue
单文件组件的 `el-link`。脚本维护文件、可见文字和完整 `href` 的 11 项清单，并要求实际集合
与预期集合一一对应；新增、删除、重复、移动到未登记文件或改变文字/目标都会失败。

脚本还要在解析每个受管开始标签时拒绝 `:href`、`v-bind:href` 及等价动态绑定，并要求恰好
一个普通字面量 `href`。选择全源码扫描而不是只读 `SourceHelp.vue`，是为了让以后在其他组件
新增 `el-link` 时必须显式扩大安全合同，不能绕过现有风险接受前提。

备选方案是使用简单 `rg` 或只搜索 `javascript:`。它们无法证明链接数量、完整目标和动态绑定
均未漂移，故不采用。引入 Vue AST 或额外测试框架可以提高通用性，但会扩大依赖与锁文件范围，
与本变更的最小安全边界不符。

### 2. 当前保持静态禁入，不提前建设运行时净化抽象

现有链接没有用户、网络、存储或规则输入。创建通用 sanitizer 或包装组件会引入尚无调用者的
策略选择，例如相对 URL 基准、端口、子域名、重定向和编码规范化，反而可能把未评审策略当成
既成事实。因此本次只允许精确静态清单并拒绝动态绑定。

若未来确需动态 URL，必须另建 OpenSpec 变更，至少定义 `http`/`https` 协议、同源或显式目标
域名 allowlist、URL 解析失败的 fail-closed 结果、重定向边界及运行时测试。届时可以在有真实
输入合同的前提下选择 `SafeLink` 或集中净化函数。

### 3. 所有受管新窗口链接显式使用 `noopener noreferrer`

11 个链接继续使用 `target="_blank"`，同时在模板上显式声明 `rel="noopener noreferrer"`。
`noopener` 隔离新页面对原页面的控制，`noreferrer` 避免固定外部工具获得来源页面信息；对
同源帮助链接统一使用同一属性，降低遗漏和条件分支。清单脚本按无序 token 集合核对 `rel`，
不依赖属性顺序或格式化布局。

备选方案是依赖现代浏览器对 `_blank` 的隐式 `noopener`。不同 WebView 与旧平台行为不适合
作为最低 API 21 项目的显式安全合同，因此不采用。只给外部链接添加隔离也会留下不必要的
例外分支。

### 4. 安全脚本作为独立 Web 命令进入现有聚合门禁

在 `modules/web/package.json` 增加独立的只读安全测试命令，并在 Web 质量任务的冻结安装后、
类型检查和构建前执行。仓库工作流契约测试同时断言该命令存在，防止未来重构 workflow 时静默
删除。测试不访问网络，也不读取 GitHub 告警状态；告警只在实施前后通过只读 API 单独核对。

实现采用 RED-GREEN：先加入清单检查和 CI/契约入口，当前模板因缺少显式 `rel` 必须产生预期
失败；随后只补齐 11 个链接的隔离属性使其转绿。不得通过降低预期数量、跳过外链或把失败改成
warning 完成 GREEN。

### 5. 构建产物必须由固定工具重建并精确对账

源模板变更后使用仓库固定的 pnpm 9.15.9 冻结安装，依次运行章节 HTML 测试、新静态链接测试、
类型检查、只读 ESLint 和完整构建。构建同步到 `app/src/main/assets/web/vue/` 的差异必须只来自
本次模板安全属性变化；任何依赖解析、无关格式化或其他页面产物漂移都阻止合并。

本变更不修改依赖版本，因此两条 Dependabot 告警预期继续为 open。若 GitHub 状态在实施期间
因上游元数据或外部操作漂移，必须记录实际原因并停止使用原快照作结论，不能把告警消失自动
描述为本变更修复了组件。

## Risks / Trade-offs

- [源码扫描不是通用运行时 URL 防火墙] → 当前动态 URL 明确禁止；扫描覆盖全部 `el-link`，
  未来动态需求必须另行设计并增加运行时验证。
- [轻量标签解析可能被复杂模板语法绕过或误判] → 解析器只接受当前简单合同，遇到无法唯一
  解析的属性、嵌套内容或重复字段时 fail-closed；不得为兼容复杂写法而静默跳过。
- [`noreferrer` 会改变来源信息] → 受管目标仅为同源帮助和固定外部工具，不依赖 referrer；
  本地 DOM 冒烟核对链接仍能按原目标打开。
- [构建同步可能产生较大压缩产物差异] → 使用固定 pnpm 与冻结 lockfile，按文件核对生成差异，
  发现依赖或无关页面漂移即停止。
- [告警继续打开可能被误认为未治理] → 提案、规范、测试和维护证据明确区分组件未修补与调用侧
  不可达；保持告警用于监测上游，不为了面板整洁 dismiss。

## Migration Plan

1. 实施开始时重新读取 `master`、11 个链接、两条告警、相关依赖版本和 Web 质量门禁；事实漂移
   时先更新本变更工件，不沿用当前快照。
2. 增加无网络静态链接合同及其 package 命令，把命令加入 Web 质量任务和仓库 workflow 契约；
   运行测试并保存因现有链接缺少隔离属性而出现的预期 RED。
3. 只为清单中的 11 个链接增加显式隔离属性，保持文字、`href`、图标、布局和 `target` 不变，
   运行聚焦测试得到 GREEN。
4. 使用固定 pnpm 冻结安装，完成网页端全部检查、构建与 Android 静态资源同步对账；在本地页面
   或既有网页容器读取最终 DOM，核对 11 个锚点的目标、新窗口和隔离属性，不访问外部目标。
5. 运行 OpenSpec 严格校验、工作流契约测试和 `git diff --check`，再只读确认两条告警仍开放且
   没有新增 high/critical 告警，随后提交人工评审。

回滚时整体撤回安全属性、测试命令、门禁入口和对应生成产物，保持依赖与告警状态不变。若测试
对合法未来需求造成阻塞，应先更新规范和设计，而不是在实现分支临时放宽清单或跳过检查。
