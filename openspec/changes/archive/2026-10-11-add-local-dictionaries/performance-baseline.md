# 本地词典性能基线

## 固定条件与阈值

首次运行性能测试前固定导入、检索、内存和磁盘门槛；新增首屏测量执行前固定 5 秒门槛，不根据结果倒推。设备为 `Legado_API_36`、`emulator-5554`，Android API 36、arm64-v8a、2560 MiB 虚拟内存，使用可丢弃 Debug 数据。

固定夹具为 100 万个不同词头、每条正文 160 字节，合计 160,000,000 字节；实际走 StarDict 导入、SQLite 磁盘索引和本地查询。冷查询指应用查询缓存未命中，不主动清除系统文件缓存；随后同词查询测量应用缓存。首屏包含弹窗及独立 WebView 的创建、查询和绘制，宿主界面已经打开。

| 项目 | 首次固定阈值 |
| --- | --- |
| 导入 | 小于 900 秒 |
| 冷查询最大值 | 小于 500 毫秒 |
| 缓存查询最大值 | 小于 100 毫秒 |
| 卡片首屏 | 小于 5,000 毫秒 |
| 应用进程 PSS | 小于 512 MiB |
| 词库副本及索引占用 | 小于 2 GiB |

PSS 在导入期间每 50 毫秒采样，并与全部查询、首屏结束后的进程值比较；不是系统全部进程或所有渲染阶段的连续峰值。首屏使用 API 36 的绘制完成回调，不为测量开启词库脚本。

## 测量结果

| 项目 | 首次基线 | 完整实现复测 | 最终 APK 复测（2026-10-11） |
| --- | --- | --- | --- |
| 导入 | 36,663 毫秒 | 43,744 毫秒 | 58,400 毫秒 |
| 六个位置冷查询 | 3、1、1、1、1、1 毫秒 | 5、2、2、1、1、1 毫秒 | 7、1、2、1、1、2 毫秒 |
| 同词缓存查询 | 1、1、0、1、0、1 毫秒 | 1、1、1、1、0、1 毫秒 | 1、1、2、1、2、1 毫秒 |
| 三次首屏 | 尚未测量 | 780、389、461 毫秒 | 1,204、592、739 毫秒 |
| 采样及结束值最大 PSS | 193,159 KiB | 233,957 KiB | 232,431 KiB |
| 原文件副本及索引 | 499,416,995 字节 | 499,416,995 字节 | 499,416,995 字节 |

复测由 `DictionaryPerformanceTest` 执行，实际输出 `OK (1 test)`，报告为 `dictionary-performance.json`；全部预先阈值满足。首屏查询使用独立的应用单例服务，系统文件缓存已由先前检索预热。

检索使用精确、规范化及繁简的 SQLite 索引，按偏移读取相关正文；百万级样本分别检索首部、中部和尾部，并不在每次查询遍历整个词库。缓存包含键和正文的计费、淘汰，不持有数据库或文件句柄。

## 固定处理边界

文件组、解压数据及正文与资源各有 8 GiB 的累计上限；MOBI 原文件为 256 MiB，解压正文为 512 MiB。2026-10-11 用户提供的《汉典》正文为 313,849,470 字节，因此在保留原文件、单词条与累计资源边界的前提下提高正文上限；真机导入结果另记入验证记录。单条正文或资源 16 MiB，MDict 数据块 64 MiB，词头 16 KiB，词条总数 500 万，文件及资源条目 10 万，目录深度 64，单次候选或义项 64，别名深度 16，查询缓存 4 MiB。内嵌资源的新增目录也计入条目限制；超过候选上限给出错误，不静默丢弃义项。

用户四本真实 MOBI/PRC 在 4 GB 内存的 API 30 真机顺序导入耗时 949.729 秒。导入后半段的 5 秒间隔采样最高观测 PSS 为 788,977 KiB，超过本记录合成样本的 512 MiB 基线；不将合成样本指标扩展为所有商业词库的保证，也不视为低内存设备已验证。查询仍使用发布后的独立磁盘索引。完整证据和采样范围见验证记录中的真机试用部分。

最终复测前恢复设备物理显示设置；最终原始输出与 JSON 保存在 `app/build/reports/local-dictionaries-final/`，全部固定阈值仍满足。此结果适用于上述固定模拟器及样本，不能宣称所有真机、商业词库和复杂样式都有相同延迟。
