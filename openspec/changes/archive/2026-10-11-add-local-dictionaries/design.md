## 背景

动机及范围见 [提案](proposal.md)。当前 `ReadBookActivity` 已把选中文字交给 `DictDialog`；`DictRule.search` 执行在线规则，现有本地导入读取的是规则 JSON。弹窗使用基础富文本，不能直接承载复杂资源。`app/lib/mobi` 已有容器、解压及通用索引代码，但缺少词典专用词头和词形处理，且普通阅读对象初始化会遍历正文。现有压缩工具接收 ZIP、RAR、7z，尚无完整的分卷读取流程。

已有书籍实体没有统一语言字段。本设计使用全局上次选择，不增加书籍语言推断或按语言路由，也不改动 `ReadView` 的词边界和选区算法。

## 设计目标与边界

格式适配、语言候选、索引和展示各自独立，在 `app/` 现有模块内建立清晰接口。七类格式进入同一首版任务，逐类验证；不能将格式识别成功当成词条可查询。产品行为以三个增量规范为准。

不把本地词典伪装成 URL 规则，不向 Rhino 暴露词库内容执行入口，不替换普通电子书解析流程，不引入完整桌面词典应用或 Python 运行时。原生解析组件只有在最低 API 21、目标平台打包及许可证条件验证后接入。

## 关键决策

### 一、独立的格式适配接口

数据流为：文件探测 → 词典及资源解析 → 内部磁盘索引 → 候选查询 → 受约束的释义展示。每个适配器提供格式探测、元数据、词头及别名迭代、词条正文和资源读取能力；通过统一错误模型报告损坏、缺文件、版本不支持、受保护及资源不足。

| 格式 | 最低实现与样本要求 |
| --- | --- |
| MDict | MDX 词头、正文、链接式别名，MDD 及分卷资源、外置样式；对实际版本、编码与资源变体分别记录证据 |
| StarDict | IFO、IDX、DICT 文件集，IDX 压缩、DICT 的 dictzip、SYN 别名、32/64 位偏移及不同正文类型；资源目录和资源包 |
| MOBI/PRC | 词典专用词头与词形索引、语言信息、词条起止；无压缩、PalmDOC、HUFF/CDIC，实际编码与混合文件索引定位 |
| DSL | 正文及 dictzip、词条标记、别名、图片音频与配套资源包；可解析的词库内引用 |
| DICTD | INDEX、DICT 及 dictzip，索引到正文的正确偏移和长度 |
| XDXF | XML 词条、正文标记、资源及压缩形式；与 StarDict 中的 XDXF 正文复用转换层 |
| BGL | 词头、正文、别名、编码及内嵌资源；不混同文本 GLS 格式 |

上述为测试目标，不是已验证清单。实施前段生成兼容性矩阵，逐项记录格式版本、压缩、编码、资源、测试来源及预期结果。每类必须完成代表性正反样本；不支持的变体需要可识别的错误，不得静默丢失查询语义或私自移出整个格式家族。

MOBI 首先验证 `libmobi` 在词典索引和资源提取上的适用性，现有 Kotlin 容器和解压代码是替代实现基础；两者封装在相同适配器后面。其他格式优先复用可维护且许可证兼容的解析代码，必要时实现有限的格式读取器。具体库是适配器内部选择，所有候选都要完成相同样本和资源成本验证，不以此改变用户行为或七类任务。

不采用“全部先转普通 EPUB”路线，因为词形、别名和边界可能在转换中丢失；不直接嵌入 GoldenDict-ng，它的桌面框架与本工程不匹配。

### 二、导入阶段处理重工作

通过系统文件选择器读取文件、多个配套文件或目录。单个文件的授权不代表能访问同目录资源；发现缺少文件时引导补选配套文件或目录，不假设拥有父目录权限。

外层 ZIP、普通单卷 RAR、7z 复用现有解压基础，tar.gz 增加入口与能力验证。归档内容仍需格式探测；词典内的 dictzip 属于适配器能力。分卷及带密码的归档给出先解压的提示。

导入顺序：复制到独立暂存目录 → 文件组探测及内容摘要 → 校验与解析 → 索引和资源构建 → 校验产物 → 原子发布并登记可用状态。文件数量、声明及实际解压大小、单条正文和内存分配均设置限制；规范化路径后检查目录边界，拒绝绝对路径、越界链接及目录穿越。使用宽位偏移并检查溢出。

所有文件与索引操作在后台执行，显示进度并允许取消。首版不要求进程终止后断点续传；重启时识别未完成暂存任务，清理并提供重试，不能将其显示为可用。现有词典在新版本完整发布前继续可用。

导入文件及资源复制至应用管理目录，避免查询依赖长期外部 URI 权限。完全相同的文件组通过内容摘要去重；同名不同内容允许并存，用独立身份和导入信息区分，不能直接覆盖。首版不提供自动替换或自动更新词库。

### 三、目录与索引分离

主 Room 数据库存储稳定词典 ID、显示名、格式、词库语言、文件组摘要、内部路径、状态、排序、资源缺失信息和索引版本。索引按词典独立保存；包含原始词头、精确键、查询候选键、别名或词形关系、词条 ID、正文定位以及资源映射，允许一个键返回多个义项。

根据格式选择保存解析后的正文或按记录读取原文件，但禁止每次查询重新解析整个词典。对热点词条和解压记录采用有界缓存，检索与长正文展示均可取消。索引升级在旁路构建成功后切换，失败保留原可用副本；索引损坏显示重建状态并允许重试。

主库只管理目录，避免百万级词条拖慢日常数据库迁移及普通备份。索引可重建，不作为唯一原始数据。删除只移除应用内副本、资源及索引；正在读取时先取消任务或延迟释放，不能影响外部原文件。

### 四、手动触发与全局记忆

沿用选词菜单中的“词典”动作，不监听选区变化自动查询。传入原始选中文字；查询服务只对检索候选作有限处理，不修改阅读页文本。

新增本地来源类型，与已有在线规则共享弹窗入口但保持独立数据模型。已选择本地词典时，下一次打开优先使用该本地 ID；切换到在线来源必须是显式操作，不能因未命中自动触发网络。在线规则保留原有能力，进入在线来源不清除上次本地词典记忆。尚未导入本地词典的旧用户仍可以主动使用已有在线来源，并看到本地导入入口。

只记忆一个全局本地词典 ID，跨书籍和应用重启保留。不增加每本书或每种语言的默认词典。第一次只有一本可用本地词典时直接使用，有多本且无有效历史时展示选择；历史词典已被删除或不可用时说明原因并让用户重新选择，不静默跳到其他词典。用户切换即持久化选择，即使该次未命中也不撤销。

查询附带递增请求标识；切换、关闭弹窗或生命周期结束时取消旧任务，结果提交时再次检查标识。保留阅读位置及选词操作，关闭弹窗不跳转书籍。

### 五、匹配策略独立于选择逻辑

按优先级查询：原始词头精确命中 → 词典自带别名和词形 → 受限规范化及额外语言候选。保留原始文本；空白、大小写等处理不能覆盖精确结果，不能删除可能属于词头的内部标点。

英文使用经过不规则词和反例验证的离线词形候选，不能用简单删除后缀冒充还原。中文按繁简转换关系产生有限候选，原词优先；多对一或一对多关系保留多个候选及实际词头，不合并原始词条，也不把简体正文强行显示为繁体或反之。古汉语通假关系仅在词库明确声明别名时采用。日韩语使用原文和词库已有映射，不承诺额外活用还原。

候选数量、跳转深度与循环检测有明确上限。先按原词返回准确结果，不把全语言模糊搜索作为默认兜底。卡片显示查询词和实际词头；同一词头有多个义项时完整呈现，多个候选词条时允许区分和选择。

### 六、受约束的富文本与本地资源

使用独立配置的 WebView 展示经适配器转换和清理的正文，以保留基础 HTML、CSS、表格、图片及音标；不用现有基础 TextView 渲染器承担全部格式，也不复用开放网页浏览器的权限设置。

关闭 JavaScript、文件通配访问和自动网络请求；资源通过应用控制的本地域名或等价拦截机制解析到当前词典资源，兼容 API 21。验证每次资源路径和内容类型，拒绝越界、脚本、远程嵌入、自动跳转和不支持的协议。页面中的远程链接不在词典视图直接导航，仅在用户明确选择后交给外部浏览器。

词库的内部链接及别名转换为词条 ID 查询，具有可返回的浏览历史；缺少目标和循环引用显示明确结果。音频链接转换成受控播放操作，使用本地媒体能力，关闭或切换词典时停止播放。尊重用户字号和日夜主题，对复杂样式提供合理降级；必需释义不得因为脚本折叠而无提示消失。缺少可选资源时保留文字并显示缺失提示。

卡片允许滚动和展开，展示完整词条，不拼接下一条正文。正文渲染和词条检索分别测量，长词条资源按需加载，不一次预载整本词库。

### 七、备份与迁移

在现有备份中加入有版本的本地词典清单和设置，保留 `dictRule.json` 原有结构。清单使用内部身份及内容摘要，不输出设备绝对路径。普通备份不含词典文件和索引；可选完整备份带上原文件、资源及校验信息，不包含可重建索引。

恢复时先校验清单、路径和摘要。与已有文件组相同则复用，不同内容不按名字覆盖；导出身份映射到恢复后的本地身份，重新建立上次选择。清单缺少原文件则保留“待重新导入”，不能显示为可查询。完整备份后台重建索引，成功后发布；取消和空间不足不破坏已有词典。重新导入匹配的文件组后将待导入记录恢复为可用。

主库新增表和偏好迁移应为增量操作，不要求现有用户迁移在线规则；实施时从当时的数据库版本添加迁移并导出结构。旧版备份缺少新清单时走原恢复流程，不清空现有本地词典。未知的新清单版本不做破坏性恢复，给出提示并保留可恢复的原有备份内容。

回滚以应用功能开关或修复发布为主：可停用新入口而保留用户文件与旧在线能力，不承诺数据库降级。迁移失败不得删除用户数据库或词典；重建索引和重新导入提供局部恢复路径。

## 风险与取舍

- 多格式的编码、压缩及资源变体较多 → 先建立逐类样本矩阵，再接入具体库；七类各自有验收任务，局部失败不能包装成全部支持。
- 原生库增加构建与内存风险 → 验证最低 API、发布架构和当前打包要求，记录许可证、维护状态与已知修复；不随意升级固定依赖。
- 中文繁简多义及词形误匹配 → 精确命中优先，候选可追溯，保留原词条，增加负向样本。
- 大词库导致内存、空间和长时间导入 → 流式或分批处理、独立磁盘索引、容量检查、可取消任务和资源限额；发布前记录测量结果。
- 词库包含网页与路径内容 → 本地资源隔离、内容清理、脚本禁用和路径校验，覆盖压缩包与备份恢复两个入口。
- 受限展示与原作者样式不完全一致 → 优先保证释义完整、可读和离线资源可用，明确不支持的交互，避免静默丢失内容。

## 验证与实施门槛

先固定公开可复现或自建的最小词库夹具，记录来源、许可、内容摘要及预期词条；社区商业词典仅作为人工兼容方向，不提交词库本体。七类格式分别覆盖正向导入、损坏输入、边界及相关资源。MOBI 另覆盖三种压缩、跨记录词条和词形；MDict 覆盖链接别名和配套资源；StarDict 覆盖多文件、别名、正文类型和偏移宽度。

兼容性试验必须在接入界面前记录选定解析方案。性能验证使用明确设备、词库规模和冷热查询条件，记录导入耗时、内存峰值、磁盘占用、查询及首屏时间；根据基线在实现查询链前固定可检查的回归阈值，不在缺少实测时宣称延迟达标。大型词库至少覆盖百兆级正文和百万级词头的合成或可复现样本，并验证每次查询不遍历整本词库。

使用解析、候选、原子导入和备份单元测试，加 Room 迁移测试及 Android API 21、主流版本、API 36 的适用设备测试。展示覆盖日夜主题、字号、旋转、长释义、稀有字符、图片、表格及本地音频。只在测试构建中使用可丢弃数据，不触碰用户正式版内容。最终执行单元测试、静态检查、调试包构建、OpenSpec 严格校验和补丁检查；未执行的设备矩阵明确登记。
