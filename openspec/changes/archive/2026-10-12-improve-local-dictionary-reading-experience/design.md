## 目标与非目标

### 设计目标

- 将语言、首选、候补、选区状态和短释义策略做成可独立验证的业务决策，Android 组件负责接入生命周期与显示。
- 复用每本词典的读取、缓存、索引、资源和恢复机制；结果携带查询语言、实际来源、命中词头与匹配来源，避免界面猜测。
- 保证原词条和已有用户文件可恢复；新的摘要、偏好和身份表示不能成为唯一的数据副本。
- 以聚焦单元测试驱动行为，再验证 Room、文件授权、阅读手势、WebView 和真实绘制。

### 设计边界

- 不新建跨模块词典工程，不替换 Rhino、普通电子书解析或阅读分页引擎。
- 不通过生成式服务制作释义，不执行词库脚本，不新增自动联网路径或运行时依赖。
- 不建立共享资源全局引用计数系统；显式共用的资源仍随各词典保留独立副本，删除互不影响。
- 不把技术性能测量视为新增学习功能或扩大词库支持承诺的授权。

## 设计决策

### 一、在现有读取层上增加可测试的查询组织

现有 `LocalDictionaryStore.lookup` 和 `byId` 继续负责单本读取。其上增加查询计划与协调职责；语言判断、来源排序、去重、候补停止条件和默认设置更新均不直接依赖 Activity、Room 或网络。

请求包含原选中文字、明确的查询语言或待选择状态、书籍身份、选区代次和请求代次。查询计划是用户设置的快照：先查首选，仅在确认未收录时依次查候补，首个候补命中后停止自动查询。其他词典由用户主动展开时查询，不预加载所有全文。

返回值明确区分命中、未收录、需要语言或词典选择、词典不可用、读取错误和取消。只有未收录触发自动候补；损坏、资源限额或首选失效必须可见，不伪装成未命中。候补成功、查看其他词典和全文导航不会修改首选；只有显式设置首选才持久化。

复用原有请求标识，并把书籍、选区代次和视图生命周期纳入结果提交条件。取消、换书、翻页、拖动和关闭阻止旧摘要、全文及资源回调更新界面。

取舍：单本查询底座已经可用，增加组织层便于验证“调用哪些来源”；自动并行遍历所有词典会扩大阅读干扰与正文开销，不符合本轮首选优先的决定。在线继续走原有显式 `DictRule.search`，不进入本地候补列表。

### 二、语言设置与按书开关分别持久化

- 在词典私有偏好中保存有版本的查询设置：每种语言的首选 ID、有序候补 ID、用户明确指定的词库语言及旧选择迁移标记。候补去重并排除首选，不把全部已导入词典默认加入。
- 词库原始语言元数据保留；用户指定值作为覆盖，索引重建不能覆盖用户选择。无语言的词库仍可手动使用，不能自动归入英文或中文。
- 按书即时开关添加到现有 `Book.ReadConfig`，缺失字段和旧 JSON 均解释为关闭；不建立第二份书籍开关映射。可选的本书查询语言提示仅保存用户明确选择，跟随现有书籍备份。
- 默认词典以明确的查询语言选择。语言提示和可靠的输入信息用于辅助；纯拉丁文字不一概断言为英文，纯汉字不一概断言为中文，混合或证据不足时显示语言选择。用户可以修改明确选择，查询不修改书籍内容或全局应用语言。
- 上次全局词典仍作为迁移输入：若有效且语言明确，初始化该语言首选；语言不明时保留 ID 并提示分类。已有新设置不能被再次升级或恢复旧备份覆盖。其他语言继续保留原文与词库映射，不承诺新增活用处理。

取舍：直接使用应用语言或“ASCII 就是英文”的规则会影响非英语词库；允许用户明确设置更可预测。按书开关使用现有序列化，可避免不必要的书籍表结构变化。

### 三、即时释义接入原有选区，使用轻量阅读内卡片

由阅读宿主拥有即时卡片和查询任务。阅读器只提供稳定初选及失效事件，不直接依赖词典存储。模式关闭时不增加自动查询；模式开启且初次长按完成稳定单词选区时开始查询，同时保留文本操作菜单和选择符。

即时卡片不调用原有菜单操作完成后的统一清除选区逻辑，不抢占阅读触摸。依据现有选区坐标选择不遮挡当前选词和菜单的可用区域；小屏或横屏空间不足时保留可收起的查询入口和全文操作，不改变正文分页。

拖动开始即取消自动查询并收起旧结果，拖动过程中不连续查词；拖动后的多词或多行选区继续通过原菜单主动查询。重新长按可以建立新的即时请求。关闭卡片、复制、标注、翻页和换书均使旧请求失效，不自动重新弹出。

主动菜单查词和即时卡片共享查询组织；全文继续复用改进后的 `DictDialog` 及本地媒体、链接、资源逻辑。旋转后恢复书籍开关，旧坐标和旧视图请求不能复用。

上述“拖动后通过菜单查询”和“小屏降级”是保留既有操作的实现约定，不增加自动整句翻译或额外分词系统。中文初选质量用真实手势验证；本轮不擅自改变已有词边界算法。

### 四、短释义是可选展示数据，全文始终保留

查询组织完成词条读取后，在后台进行释义预处理，生成实际词头、可选音标及词性、可靠短释义、来源和全文。摘要提取与索引文件格式分离，已有词典不因新卡片被迫重新导入或全量重建。

优先利用词库已有结构和经过样本验证的明确标记；自由 HTML 使用有限、可解释的策略。不能把任意正文前若干字符、版权段落、词头或词性当作释义。无法确定释义边界、遇到依赖脚本的折叠或复杂布局时返回无可靠摘要状态，卡片展示经过约束的原词条并保留全文入口。

摘要和全文都保留原始词条，字段缺失时不生成音标、词性或例句。摘要长度只影响已识别释义的展示，不用于判断其可靠性；省略须可见并能打开全文。多个真实词形候选分别标明词头，不能不可逆地合并成一条摘要。

短释义以原生轻量视图展示；全文继续使用受限 WebView。HTML 解析、清理与样式处理在后台完成，UI 仅绑定结果和启动绘制。停止重复追加应用词头标题，保留词库自己的正文与结构。已有资源路径校验、网络禁止、脚本禁止、手动媒体及生命周期约束不变。

取舍：在导入时强制生成所有摘要会增加大词库导入成本并迫使旧索引升级；本轮选择查询时预处理并有界缓存。缓存键包含词典身份、词条、摘要策略版本及必要主题信息，不持有视图或数据库句柄。

### 五、语言候选以正确性为约束

原文精确词头、词库声明的别名与词形保持优先；必要规范化与繁简候选继续可追溯。额外英文候选只用于明确英文查询，不用于未定语言或其他语言词库。

首先为 `singing`、`wolves`、`knives`、`leaves` 及既有正反例写测试。候选应能解释为真实词形关系；避免把去掉末尾字母且词库恰好收录当成正确还原。`singing` 不能因通用去 e 规则优先落到 `singe`；`leaves` 等存在真实歧义时保留可区分的词头，不能因第一候选命中而隐藏其他有效候选。

词库自己的原词与映射仍覆盖额外算法，不要求实现完整语言学分析。修正集中于现有候选模块与查询优先级，保留候选、义项、正文和循环上限。错误或超限继续明确报告，不静默截断。

### 六、文件组清单和版本化身份替代整父目录身份

授权目录或归档可以整体进入临时发现区，但发布副本与摘要只使用选中词典的文件组。文件组解析复用各格式知识：主文件、必要配套、相应资源包和已确认外部资源；无关的其他主词典、其配套和未关联目录不纳入。

归属不明时提示用户补充关联，不能以“可能有资源”为由复制整个父目录，也不能静默丢弃已引用的必要资源。显式共享资源允许独立复制。保留七类格式与现有路径、授权、符号链接和体积边界，解析器正文能力不重写。

新文件组保存版本化相对路径清单，用选中的主文件、规范化相对路径和文件内容计算版本 2 摘要；父目录位置和无关兄弟文件不参与。正文或已关联资源实质变化仍产生不同内容身份。

在 `LocalDictionary` 上增加身份版本字段，旧记录默认版本 1；目前预计 Room 76→77，实施前如仓库版本已变化则从实际版本递增。查询索引格式仍为版本 2，不因 Room 迁移改写查询索引标记。

已有可用版本 1 记录先保持可查。后台从应用内原文件确定实际文件组并验证后，原子更新身份版本、摘要、文件组清单和旧摘要别名，保留原 ID、排序、文件与索引；取消或判断不明确时维持旧记录。迁移过程中不删除旧副本里多带的文件，空间清理不作为本轮自动行为。新导入与旧记录比较时同时支持已验证的版本 2 身份和旧摘要别名，不能按名称去重。

旧版仅清单备份若混入兄弟文件摘要、又缺少原文件，就无法由单独主文件可靠还原旧摘要。此时保留待导入 ID 和引用，提供用户明确重新关联入口；不声称能够自动恢复，也不删除或静默覆盖不同内容。

### 七、备份升级采用版本 2，版本 1 保留专用校验路径

新清单保存词典身份版本、已验证旧摘要别名、文件组信息和查询设置；按书开关与语言提示通过现有书籍 `ReadConfig` 备份。普通备份不包含文件或索引，完整备份只带实际文件组及资源，不再复制整父目录。

版本 1 完整备份必须先用旧摘要算法验证原文件组，再做文件组归一和 ID 映射，不能直接套新摘要而报告损坏。版本 1 普通备份恢复旧选择并保留待导入状态；已有新设置保持，缺失语言采用明确分类。版本 2 校验身份、文件组边界及内容后恢复，再映射首选、候补和用户语言指定；不可用引用可见标记，不替换成另一同名词典。

旧选择字段保留为兼容信息，但旧应用遇到新清单应按已有未知版本逻辑提示限制；不承诺数据库降级或新备份可在旧应用完整恢复。未知更高版本不破坏已有数据和可独立恢复的在线规则。恢复及新设置发布保持可取消、后台与原子原则。

### 八、以红绿重构组织实施证据

每项新增或修正行为使用以下小循环，全部完成后再进入下一项：

1. 写一个能表达用户可观察结果的聚焦单元测试，准备最小夹具；运行目标测试，确认因目标行为缺失或错误而失败。
2. 记录命令、用例、预期与实际失败原因。编译错误、缺 SDK、无效夹具、超时环境故障不算行为红灯；原测试通过只能作为兼容基线。
3. 只实现使该测试通过的行为，运行目标测试及受影响回归；不提前实现下一项。
4. 测试持续通过时再整理必要代码，整理后重跑相同测试；没有必要的重构可明确跳过。

新接口需要最小类型声明或测试装置才能运行时，先写测试，随后仅补足编译所需声明，不提供目标行为；该准备与第一次行为失败都记录。Android 专属行为以设备测试补充，不用测试私有方法、复制算法或仅验证模拟对象来替代真实路径。可注入的读取边界用于证明只查询指定来源、取消隔离及不调用在线；正文、文件组和迁移仍使用真实最小数据。

实施记录建立在本变更的 `verification.md`，原始输出位于忽略的报告目录。逐行为记录红阶段、绿阶段、重构回归、设备结果与未执行范围；本提案阶段不创建已通过记录、不写测试或业务代码、不勾选实现任务。不下载或安装 Superpowers。

## 风险与取舍

- 即时卡片与拖动、菜单竞争 → 仅稳定初选触发，代次隔离，拖动撤销，模式默认关闭，真实手势回归。
- 语言元数据缺失或脚本无法区分语言 → 保留用户指定与原始元数据，无法可靠判断时选择，不自动把所有拉丁词交给英文还原。
- 摘要抽取错误或释义丢失 → 有限可信策略、正文原样保留、负向夹具、原词条降级及真实词库人工核验。
- 旧摘要含无关文件 → 版本化算法、已验证别名、原 ID 保留、旧完整备份先旧校验、缺文件时明确关联。
- 新候补增加延迟 → 有序短路、用户指定集合、按需其他来源、可取消及有界缓存。
- API 21 WebView 与主题差异 → 摘要优先原生显示，完整展示延续现有权限和设备矩阵，不升级固定依赖。
- 大型 MOBI 内存和取消响应仍不足 → 用相同授权词库和设备单独测量并登记；若本轮未改原生提取，明确保留限制，不扩张性能保证。

## 迁移与回退

1. 先建立失败的设置解码、旧选择、身份和备份用例；再增加有默认值的 Room 身份版本字段及结构快照，验证旧书、在线规则和词典清单保留。
2. 引入查询设置版本 2，迁移已确认语言的旧选择；按书开关缺失即关闭。迁移重入不得覆盖用户后续选择。
3. 原词库及索引继续可用，版本 1 身份在后台逐组验证和升级；不启动全量词库重建，不在启动主线程扫描大文件。
4. 启用按语言查询与候补，再接入短释义和按书即时模式，逐项完成测试循环；旧菜单在所有阶段可用。
5. 验证版本 1、版本 2、缺失清单和未知版本的恢复；发布前对照增量规范核验。
6. 回退首先关闭按书即时开关或停用新卡片，保留查询数据、文件和原菜单。通过向前修复恢复旧行为，不降低 Room 版本、不删除词库、不用破坏性迁移回退。

## 验证计划与固定口径

以单元测试覆盖候选、语言与查询计划、选区状态、摘要降级、文件组、身份和清单解码；以设备测试覆盖 Room 迁移、真实目录授权、索引、阅读手势、绘制、资源和恢复。

短释义性能在新测试首次执行前固定以下目标，失败后不通过放宽阈值来宣称完成：使用既有 API 36 固定模拟器和百万词头、160 MB 正文样本，另加入可可靠提取摘要与复杂正文夹具。首屏从稳定初选或菜单查询触发到释义实际可读计时，包含查询、预处理和绘制，阅读宿主已打开；分别报告新进程与同进程重复，不能把系统文件缓存描述为已清除。

- 可可靠提取摘要的首屏：至少 3 次新进程首次查询，每次不超过 1,000 毫秒；至少 10 次同进程重复查询，每次不超过 500 毫秒。
- 长正文查询或预处理未完成时，关闭与切换的 UI 响应不超过 150 毫秒，迟到结果不得出现。
- 完整词条在相同固定夹具上的首次绘制沿用 5,000 毫秒回归底线，复杂真实词库单独报告；这不替代短释义目标。
- 原有单本索引、导入与存储固定阈值继续回归；真实大型 MOBI 单独记录导入耗时、观测内存、取消请求至任务结束时间，不能套用 StarDict 的合成内存阈值。

设备验证覆盖 API 21、主流 Android 和 API 36；没有设备时仅登记未验证，不把单元测试或构建成功作为设备通过。原有七类兼容夹具继续回归，新真实词库试用需记录版本、授权和范围，不提交用户商业词库。

## 可在实施中验证的事项

有限摘要策略对具体词库的覆盖率、实际中文初选效果、卡片在不同屏幕上的位置、真实大型 MOBI 的观测指标需要测量。这些测量不改变已选定的原文降级、既有选区复用和保留底座方向；若后续发现必须改动分词或替换原生解析器，应另行提出范围调整，不能直接扩展实施。
